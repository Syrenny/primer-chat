# Primer Chat

> Общая идея: Хотелось бы просматривать PDF-документы и задавать по ним вопросы в чате рядом

## Front

### Требования

-   Быстрая загрузка в Real-Time
-   Интеграция с OpenAI GPT4o
-   PDF Viewer
-   Отображение найденных фрагментов
-   Отображение процесса индексации в реальном времени
-   Кэширование файлов

### Фичи

-   Минималистичный кастомный PDF-viewer
-   Отображение найденных фрагментов в PDF-viewer с возможностью итерироваться по ним
-   Возможность объединять файлы в папки. Отдельная кнопка создать проект, затем дать ему имя и можно перетаскивать туда файлы из корня
-   Возможность запоминать информацию о пользователе, предпочтения, подстраиваться под него + делать по ходу саммари по проектам/отдельным файлам
-   Возможность порассуждать над проблемой
-   Авторизация по API ключам, по ним же контролировать доступ к моделям, функционалу, лимиты и т.д.

### Стек

React + ts + vite + Dexie.js/idb (IndexedDB дял кэширования файлов) + zustand (стейты с персистом) + shadcn для UI

## Backend

### Требования

-   Многопользовательский режим
-   Асинхронный
-   Хранение файлов в S3
-   Хранение остальной информации в PostgreSQL
-   Стриминг ответов от системы
-   Горизонтальное масштабирование воркеров для индексации и генерации

### Фичи

-   Поддержка пайплайна для рассуждения
-   Поддержка рассуждающих моделей
-   Kafka?

### RAG-индексация VLM

1. Скормить pdf по страницам в GPT, попросить сказать, что есть на странице, описать картинки и сделать краткое саммари
2. Сделать саммари по всем страницам
3. Векторизировать все получившиеся саммари

### RAG-поиск VLM

> Может быть один или несколько документов

1. Поиск по саммари документов -> top-3
2. Поиск по страницам в документах -> top-3
3. Помещаем саммари в контекст модели. Хммм, это странно. Информация едва ли будет ограничиваться тремя документами и 9 страницами


### RAG индексация, чанкинг с помощью LLM

1. Читаем с помощью fitz
2. Делаем описание для всех картинок с помощью VLM
3. Загоняем портянку текста вместе с описаниями картинок в LLM и просим сегментировать текст на фрагменты. При этом выделяем диапазоны чанков, а также еще заголовки, названия и т.д.
4. В итоге получается более или менее иерархическая структура документа + очищенная от мусора

### RAG поиск, чанкинг с помощью LLM

1. В базе чанки хранятся с указанием их иерархической структуры
2. Нужны методы, которые позволят извлекать чанки с указанными названиями, номерами в названиях и т.д. Видимо нужен полнотекстовый поиск под такие приколы
3. Нужен метод для извлечения всей иерархической структуры. Чтобы помещать ее в системный промпт
